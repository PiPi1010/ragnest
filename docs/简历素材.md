## 二、项目简介（简历"项目描述"栏，3-4 行）

基于 Spring Boot 4 + Spring AI 2.0 自研的企业级知识库平台，实现从**文档上传 → 多格式解析 → 分块向量化 → 语义检索 → 大模型问答**的完整 RAG 闭环。采用 Maven 多模块架构（10 个业务模块），后端约 4000 行 Java 代码，配套 Vue 3 前后端分离管理前端。支持 PDF/Word/Excel/Markdown 等 6 种文档格式、多轮对话与 SSE 流式输出、多租户数据隔离、JWT 认证。

---

## 三、核心工作与亮点（简历"主要工作/技术亮点"栏）

### 1. 多模块架构设计（工程能力）
- 采用 Maven 多模块分层架构，按 **common / core / tenant / security / parser / vector / ai / admin / server / sdk** 拆分为 10 个模块，模块间单向依赖、职责清晰。
- 统一规范：统一返回体 `Result<T>`、全局异常处理（`BizException` + `GlobalExceptionHandler`）、错误码分段（1xxx 通用 / 2xxx 知识库 / 3xxx 文档 / 4xxx AI / 5xxx 权限）。

### 2. RAG 核心链路（AI 应用能力）
- 基于 **Spring AI 2.0 的 Modular RAG** 抽象，实现「Query 转换 → 多路检索 → 结果合并 → 后处理」四阶段流水线（`RagPipeline`），并支持**多检索器 + 可插拔后处理器**（去重、重排序）。
- 自研 `RagAdvisor` 切面：在请求进入大模型前自动检索知识库，将召回内容注入系统提示词，实现「基于知识库的问答」。
- 向量检索基于 **pgvector**，Embedding 采用 **bge-m3（1024 维）**；向量库层抽象工厂模式，预留 pgvector / Milvus / Redis 多实现扩展。

### 3. 多格式文档解析（数据处理能力）
- 设计统一 `DocumentParser` 抽象接口，实现 **6 种格式**解析器：Markdown、纯文本、**PDF（PDFBox）**、**Word（Apache POI）**、**Excel（Apache POI，多 Sheet）**、CSV。
- 支持按标题层级分块（`MarkdownHeaderSplitter`），提升检索命中率。

### 4. 多轮对话与流式输出（交互体验）
- 实现会话持久化 + 历史上下文注入，支持**多轮对话**（对话历史存库，每轮自动拼接上下文）。
- 基于 **SSE（SseEmitter）实现流式逐 token 输出**，前端配合完成打字机效果；解决 Spring MVC 响应式返回的异步 dispatch 二次鉴权、chunked 截断等疑难问题。

### 5. 多租户与安全（架构能力）
- 自研 **ThreadLocal 租户上下文（TenantContext）+ 请求过滤器**，通过 JPA **`@PrePersist` 生命周期回调自动填充 `tenant_id`**，实现「共享表 + 租户列」的数据隔离，业务代码零侵入。
- 基于 **JWT 无状态认证**（jjwt）+ Spring Security 7，实现登录签发、请求鉴权、401/403 统一处理。

### 6. 前后端分离前端（全栈能力）
- 使用 **Vue 3 + Vite + TypeScript + Element Plus + Pinia + Vue Router + Axios** 搭建管理前端。
- 封装 Axios 拦截器（自动注入 token / 租户头、401 自动跳登录）、路由守卫、以及基于 `fetch + ReadableStream` 的 **SSE 流式对话前端**。

## 六、面试可深挖点（准备这些，面试会加分）

1. **为什么用 Modular RAG 而不是简单拼接？** —— 可插拔、易扩展多路检索与后处理（重排/去重）。
2. **多租户隔离怎么做的？** —— 共享表 + `tenant_id` 列；ThreadLocal 上下文 + JPA `@PrePersist` 自动填充，业务无侵入。
3. **流式输出踩过什么坑？** —— Spring MVC 返回 `Flux` 触发 asyncDispatch 二次鉴权 → Access Denied + chunked 截断；最终用 `SseEmitter` + ASYNC dispatch 放行解决。
4. **多轮对话如何实现？** —— 会话与消息持久化，每轮从库加载历史拼接到 Prompt；流式场景通过 SSE 首条消息回传会话 ID。
5. **文档分块策略？** —— 按 Markdown 标题层级分块，兼顾语义完整性与检索粒度。
6. **模块为何这样拆分？** —— common 基础 → core 领域 → 能力层（parser/vector/ai/security/tenant）→ 应用层（admin/server），依赖单向、便于独立演进。
